# Project rules

- Write code comments and notebook prose in natural, direct language.
- Comment only when the scientific intent, constraint, or reasoning is not obvious from the code.
- Avoid workflow-template phrases such as “Goal,” “Next step,” “canonical,” and “ground truth.”
- Treat notebooks as short research narratives: introduce the question, show the work, and briefly interpret the result.
- Do not rerun the full notebooks or rebuild the historical model results during routine repository work. Use small fixtures and focused tests instead.
