# Probabilistic Storm Tracks

This research project compares a persistence forecast with an adaptive constant-velocity Kalman filter on global tropical-cyclone tracks from IBTrACS. It prepares agency-selected best tracks, evaluates both models on the same forecast cases, and exports a versioned data contract for a Streamlit dashboard. The Python package contains the scientific logic; the notebooks and app are interfaces to that logic.

The current workflow evaluates point-position forecasts. Although the Kalman filter propagates state covariance, the project does not yet evaluate calibrated probability distributions, landfall probability, or intensity forecasts.

The screenshot uses a small fixture whose headline test split contains two storms. It is not a full-data result.

## Current status

The supported pipeline uses deterministic storm-level train, validation, and test splits. With the default configuration, the nominal fractions are 80%, 10%, and 10%, using seed 42. Kalman process covariance is estimated from training storms only; validation or test storms are then evaluated with matched persistence and Kalman origins and horizons.

The repository does not include a full-data performance result generated by this current contract. It retains an older result snapshot in `artifacts/historical_dashboard/`, but the generation record is incomplete and the current app does not load it.

See [Results and limitations](docs/results_and_limitations.md) before interpreting any tracked result.

## Quick start

Python 3.11 or newer is required.

```bash
python -m pip install -e ".[app,notebooks,dev]"
```

Preview every pipeline stage without reading the dataset or running a model:

```bash
python scripts/run_pipeline.py --dry-run
```

Run the tests and static checks:

```bash
python -m pytest -q
python -m ruff check .
```

## Data and full workflow

Download the IBTrACS v04r01 all-storm CSV from [NOAA NCEI](https://www.ncei.noaa.gov/products/international-best-track-archive) and save it as `data/ibtracs.ALL.list.v04r01.csv`, or change `paths.raw_data` in `configs/pipeline.toml`.

NOAA updates v04r01 in place. Record the access date and file checksum for every result release, and cite both the [v04r01 dataset](https://doi.org/10.25921/82ty-9e16) and its construction paper.

The full run is intentionally explicit because it can take a long time:

```bash
python scripts/run_pipeline.py --execute
```

The stages are:

| Stage | Reads | Writes | Typical cost |
| --- | --- | --- | --- |
| `prepare_data` | Raw IBTrACS CSV | `data/hurricane_paths_processed.pkl` | Long |
| `run_models` | Processed tracks | Split-named model pickles, summaries, and metadata in `data/` | Long |
| `build_dashboard_data` | Paired model results and processed tracks | Versioned Streamlit contract in `app/data/` | Medium |

The default evaluation split is `test`. `configs/pipeline.toml` also records the split seed and fractions, forecast horizons, origin sampling, and covariance settings.

To rebuild only the app contract from existing model outputs:

```bash
python scripts/build_dashboard_data.py \
  --persistence-results data/test_persistence_results.pkl \
  --kalman-results data/test_kalman_results.pkl \
  --tracks data/hurricane_paths_processed.pkl \
  --output-dir app/data \
  --headline-split test
```

Then start Streamlit:

```bash
streamlit run app/app.py
```

More detail is available in [the app guide](app/README.md).

## Evaluation contract

- Complete storms stay within one train, validation, or test split.
- Process covariance is estimated from training storms only; observation covariance uses a fixed measurement-noise floor.
- Persistence and Kalman results must contain the same storm, origin, horizon, and split keys.
- Position error is Euclidean distance in a storm-local equirectangular coordinate approximation, in kilometers.
- RMSE is the square root of the mean squared position error.
- Improvement is persistence RMSE minus Kalman RMSE, so a positive value favors the Kalman filter.
- Supported forecast horizons are 6, 12, 24, 48, and 72 hours.

## Historical result snapshot

The retained legacy summary reports lower persistence RMSE at all five horizons. Its 24,964 cases per model and horizon combine rows labeled `test` and `validation`, but the artifacts do not record the training population or enough generation metadata to establish leakage-free held-out performance. The legacy percentage field is also mislabeled: it is calculated from relative mean error, not RMSE. See [Results and limitations](docs/results_and_limitations.md) for the values and interpretation boundary.
